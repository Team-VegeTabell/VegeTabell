# 機能要件詳細

MVP機能一覧（アカウント登録・ログイン／商品出品／商品一覧表示／予約機能）を、業務ルール・異常系レベルまで詳細化したもの。
DBのテーブル定義は [db-design.md](./db-design.md) を参照。

---

## 1. アカウント登録・ログイン

**対象ロール**：買い手／売り手（登録時に選択。登録後のロール変更は不可＝1メールアドレスにつき1ロール固定）

**登録必須項目**
- 共通：メールアドレス、パスワード、表示名、ロール
- 売り手のみ追加：店舗名、住所、緯度経度、受け取り場所の説明（`shops`テーブルに保存）

**業務ルール**
- メールアドレスは一意。登録済みメールで再登録しようとした場合はエラー
- ログイン画面でロール（買い手／売り手）を選択する仕様のため、選択したロールとアカウントの`role`が一致しない場合はログイン拒否（例：買い手アカウントで「売り手」を選んでログインしようとした場合はエラー表示）
- パスワード再設定機能は **MVP対象外**（画面上の「パスワードをお忘れですか？」リンクは将来対応。現時点では準備中表示 or リンク非活性）→ 要チーム確認

---

## 2. 商品出品

**対象**：売り手のみ（要ログイン、`role='seller'`）

**入力項目**：商品名、カテゴリ、写真（**任意**）、通常価格、レスキュー価格、出品個数、引取期限

**業務ルール**
- レスキュー価格 ≤ 通常価格（DBのCHECK制約と一致）
- 引取期限は現在時刻より未来でなければならない
- 出品時、`remaining_quantity = total_quantity` で初期化、`status = 'on_sale'`
- 写真未設定の場合はプレースホルダー画像を表示
- **出品後の編集は不可**。売り手ができる操作は次の2つのみ：
  - 「完売にする」（`status`を手動で`sold_out`に変更）
  - 「削除する」
- 削除は予約が入っていない商品のみ可能（予約が1件でもあれば削除不可）→ 業務が回るか要チーム確認

**自動処理（バッチ）**
- `expiry_at`を過ぎたら`status = 'expired'`に変更し、一覧から非表示にする
- `remaining_quantity`が0になったら`status = 'sold_out'`に自動変更

---

## 3. 商品一覧表示（買い手ホーム）

**表示対象**：`status = 'on_sale'` かつ `remaining_quantity > 0` の商品のみ

**並び順**：`expiry_at`が近い順（デフォルト）

**絞り込み**：カテゴリタブ（野菜／果物／パン／惣菜）、エリア（地域名 or 現在地からの距離）、キーワード検索（商品名の部分一致）

**距離表示**：買い手の現在地（ブラウザのGeolocation取得、または選択したエリア）と店舗の緯度経度から算出し「○m」表示

---

## 4. 商品詳細

**表示項目**：写真、期限カウントダウン、商品名、店舗名＋距離、レスキュー価格／通常価格／割引額、商品説明、残り在庫数

**数量選択**：
- `remaining_quantity`が2以上の場合、数量選択UI（1〜`remaining_quantity`の範囲）を表示
- `remaining_quantity`が1の場合、選択不要で1固定
- ※現行ワイヤーフレームには数量選択UIが無いため、画面側への追加が必要（申し送り事項）

**在庫切れ**：`status = 'sold_out'`の場合は予約ボタンを非活性化し「完売しました」を表示

---

## 5. 予約機能（店頭払い）

- 予約確定操作で即時`reservations`を作成、`status = 'reserved'`
- 在庫減算：`remaining_quantity -= 予約数量`（同時予約時の整合性は今後の検討事項。[db-design.mdの未確定事項](./db-design.md#未確定今後の検討事項)を参照）
- 在庫が0になったら商品の`status`を`sold_out`に自動更新
- **キャンセル**：買い手・売り手どちらも可能。キャンセル時：
  - `reservations.status = 'canceled'`、`canceled_by`／`canceled_at`を記録
  - 商品の`remaining_quantity`を戻し、期限内であれば`status`を`on_sale`に戻す
- **受取完了**：
  - 買い手が予約詳細画面の「受け取り完了にする」ボタンを押すと、即時`reservations.status = 'completed'`に更新し、売り手に通知（`pickup_completed`）を送る
  - 押し忘れた場合のフォールバックとして、`pickup_end_at`を過ぎた時点で`status = 'reserved'`のままの予約をバッチで`status = 'completed'`に自動更新（この場合は通知なし）

## 6. 通知

テーブル定義・通知種別は[db-design.mdのnotifications](./db-design.md#notifications通知)を参照。

**画面仕様として明記する点**
- 未読件数をベルアイコンにバッジ表示
- 通知一覧で既読／未読を視覚的に区別
- 一覧をタップ（開く）した通知は既読化する
