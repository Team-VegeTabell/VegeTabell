# 認証・権限設計

「誰であるかの確認（認証）」と「何をしてよいかの制御（権限／認可）」を整理する。
URL一覧は[api-design.md](./api-design.md)、機能要件は[functional-requirements.md](./functional-requirements.md)を参照。

## 1. 認証方式

- Thymeleafによるサーバーサイドレンダリング構成のため、**セッションベース認証**（Spring Security標準のフォームログイン）を採用する。JWT等のトークン認証はSPA/REST API向けのため今回は不要
- パスワードは**ハッシュ化して保存**（平文保存はしない）。`password_hash`カラムにハッシュ値を格納
- セッションの有効期限：30分（操作が無い場合は自動的にログアウト扱い。値は運用で調整可能とする）
- 「ログイン状態を保持する（Remember me）」機能：現行ワイヤーフレームに無いため**MVP対象外**
- ログアウトはセッション破棄で実現

### ログイン時のロール確認（本アプリ特有の仕様）

ログイン画面には「買い手／売り手」の切り替えトグルがある。標準のメール・パスワード認証に加えて、**選択したロールとアカウントの`role`が一致するか**を追加でチェックする。

- 一致しない場合（例：買い手アカウントで「売り手」を選んでログイン）→ 認証エラーとして扱い、「メールアドレス、パスワード、またはアカウント種別が正しくありません」のように表示する（どちらが誤りかを具体的に教えない＝アカウント種別の推測によるなりすまし対策）

## 2. ロールと画面アクセス権限

| URLパターン | 必要ロール | 未ログイン時 | ロール不一致時 |
|---|---|---|---|
| `/login`, `/signup` | 不要 | そのまま表示 | - |
| `/`, `/products/**`, `/reservations/**`, `/mypage` | 買い手（ROLE_BUYER） | `/login`へリダイレクト（ログイン後に元のURLへ戻す） | 403エラー画面 |
| `/seller/**` | 売り手（ROLE_SELLER） | `/login`へリダイレクト | 403エラー画面 |
| `/notifications/**` | 買い手・売り手どちらでも可（要ログイン） | `/login`へリダイレクト | - |

補足：`/reservations/{id}/cancel`のみ買い手・売り手どちらもアクセスしうるエンドポイントのため、ロールでの制御ではなく「3. リソースの所有者チェック」で制御する。

## 3. リソースの所有者チェック

ロールが合っていても、**他人のデータを操作できてしまう**問題は別途防ぐ必要がある。ロールチェックとは別に、対象データの持ち主がログインユーザー本人（または本人の店舗）かどうかを都度確認する。

| 操作 | チェック内容 | 不一致時 |
|---|---|---|
| `GET /reservations/{id}` | 予約の`buyer_id`＝ログイン中の買い手のidか | 403（またはリソース秘匿のため404） |
| `POST /reservations/{id}/cancel` | 予約の`buyer_id`＝買い手本人、または予約対象商品の`shop_id`の持ち主＝売り手本人か | 403 |
| `POST /seller/products/{id}/sold-out` | 商品の`shop_id`＝ログイン中の売り手の店舗か | 403 |
| `POST /seller/products/{id}/delete` | 同上 | 403 |
| `GET /notifications`, `POST /notifications/{id}/read` | 通知の`user_id`＝ログインユーザー本人か | 403 |

## 4. その他セキュリティ事項

- CSRF対策：Spring Securityのデフォルト機能を有効にし、Thymeleafの`th:action`付きフォームでトークンを自動送信する
- SQLインジェクション対策：Spring Data JPA（プレースホルダ経由のクエリ）を使用し、文字列連結によるSQL生成を行わない
- XSS対策：Thymeleafの`th:text`はデフォルトでHTMLエスケープされるため、ユーザー入力（商品説明・表示名など）はエスケープされた状態で表示する

## 申し送り事項

- セッションタイムアウトの具体的な時間（30分と仮置き）はチームで最終確認
- 権限不足（403）画面のデザインは、現行ワイヤーフレームに含まれていないため別途用意が必要
